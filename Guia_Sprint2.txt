> "Implementa autenticación JWT en Express con estas rutas en `src/routes/auth.js`:
>
> POST /api/auth/register — recibe { email, password, nombre }, hashea password con bcryptjs (salt 10), crea usuario en tabla users, devuelve { token, user: { id, email, nombre, onboarding_completado } }. Validar que email no exista antes.

>
> Crear `src/middleware/auth.js` que extrae el Bearer token, lo verifica con JWT_SECRET del .env, y agrega req.user = { id, email } al request. Si no hay token o es inválido, devolver 401.
>
> El JWT expira en 7 días. Usar la tabla users del schema PostgreSQL ya creado."
Definition of Done:
POST /api/auth/register crea usuario y devuelve token
POST /api/auth/login con credenciales correctas devuelve token
POST /api/auth/login con credenciales incorrectas devuelve 401
GET /api/auth/me con token válido devuelve datos del usuario
GET /api/auth/me sin token devuelve 401

Restricciones críticas para prompts de vibe-coding
Estas son las cosas que más rompen al usar Claude Code/Antigravity sin supervisión:
1. Siempre verificar que los UUIDs se generan en la DB, no en JS.
Nunca `uuid()` en JavaScript. La DB usa `DEFAULT gen_random_uuid()`.
2. Los decimales de dinero son DECIMAL(18,4) en PostgreSQL, no float.
Si Claude Code usa `parseFloat()` para guardar precios, puede perder precisión. Guardar como string en el query parametrizado.
3. Las FK siempre van con el negocio.
Antes de cada INSERT que tenga un FK a otra tabla del mismo negocio (ej: categoria_id en insumos), hacer un SELECT para verificar que ese ID pertenece al mismo negocio_id. Si no, devolver 403.
4. El motor de cálculo es una función pura en services/, no en el controller.
Si Claude Code pone toda la lógica en el controller, es más difícil de testear y debuggear. Insistir en la separación.
5. Siempre usar try/catch en todos los controllers.
Un error sin catch derrumba Express. El patrón mínimo:
```js
try {
  // lógica
} catch (err) {
  console.error(err);
  res.status(500).json({ error: err.message });
}
```
6. Las transacciones en PostgreSQL con pg:
```js
const client = await pool.connect();
try {
  await client.query('BEGIN');
  // operaciones
  await client.query('COMMIT');
} catch (e) {
  await client.query('ROLLBACK');
  throw e;
} finally {
  client.release();
}
```
El onboarding y el seed DEBEN usar transacción.
7. Para el frontend: el negocioId activo va en un Context.
No pasarlo como prop por 5 niveles. Si Claude Code lo empieza a propdrilling, pedirle que cree un `NegocioContext`.
8. CORS en desarrollo:
El backend necesita `cors({ origin: 'http://localhost:5173' })` para que Vite pueda llamarlo.
